# 2026 年全国大学生电子设计竞赛 H 题：智能循迹小车

基于 **TI MSPM0G3507（天猛星开发板）** 的智能循迹小车项目，面向 2026 年全国大学生电子设计竞赛 H 题。系统采用 8 路数字灰度传感器进行赛道检测，通过 TB6612FNG 驱动双路直流减速电机，结合 PD 差速控制、OLED 菜单和多任务状态机，实现循迹行驶、定点停车、计时及 UART 摆杆控制板通信等功能。

## ✨ 项目功能

- **8 路灰度循迹**：采用加权质心算法计算赛道偏差。
- **PD 差速控制**：根据偏差动态调整左右轮速度。
- **弯道优化**：结合误差滤波、弯道降速和输出斜率限制，改善循迹稳定性。
- **丢线处理**：短时保持原方向，超时后按照最后一次有效方向搜线。
- **精准停车**：通过状态机识别 A 点，并结合车尾补偿与制动逻辑完成停车。
- **多任务支持**：通过 OLED 菜单选择 EVENT2～EVENT6 对应的任务。
- **计时与里程统计**：支持行驶计时、编码器计数和里程累计。
- **OLED 交互**：显示菜单、任务状态及运行结果。
- **UART 通信**：通过 UART2 向 STM32 摆杆控制板发送控制报文。
- **急停保护**：停止按键具有最高优先级。

## 🧠 核心算法

### 1. 灰度加权质心

8 路探头依次设置权重：

```c
-7, -5, -3, -1, +1, +3, +5, +7
```

程序根据压线探头计算赛道偏差。少量探头压线时保留较大的边缘误差，多路探头压线时采用加权平均，得到用于循迹控制的偏差值。

### 2. PD 差速控制

根据偏差计算修正量，并调整左右轮速度：

```text
左轮速度 = 基础速度 + 修正量
右轮速度 = 基础速度 - 修正量
```

默认不使用积分项，采用 PD 控制。不同任务配置不同的控制参数，以适应速度与稳定性的需求。

### 3. 弯道与丢线处理

- 对偏差进行低通滤波，减少数字传感器切换造成的抖动。
- 弯道时适当降低速度。
- 对 D 项进行滤波，并限制控制输出变化幅度。
- 短时丢线时保持原有转向趋势。
- 持续丢线时按照最后一次有效方向进行搜线。
- 全部探头压线时按停止线或十字区域进行特殊处理。

### 4. EVENT2 定点停车

采用分阶段状态机：

1. 确认小车已经离开 A 点。
2. 等待武装时间结束，避免起步时误判。
3. 连续检测到符合条件的压线状态后，确认返回 A 点。
4. 根据一圈耗时和车身长度计算车尾补偿时间。
5. 通过电机制动与短时反转调整车身姿态，最后停车。

停车效果依赖赛道尺寸、车速、制动距离和实际标定结果。

### 5. 编码器与 UART 通信

编码器用于速度显示和里程累计，当前方案主要使用 A 相进行计数，不参与电机闭环控制。

UART2 采用 115200 baud，发送固定长度 5 字节报文：

```text
0x5A [state] [modenum] [checksum] 0xA5
```

其中：

```text
checksum = state ^ modenum
```

该通信功能用于向摆杆控制板发送任务及运动状态指令。

## 🚀 编译与运行

1. 安装 TI Code Composer Studio，并准备匹配版本的 MSPM0 SDK。
2. 导入本项目工程。
3. 检查 SysConfig 外设配置、引脚映射和时钟设置。
4. 按照实际硬件连接灰度模块、电机驱动、编码器、OLED 和按键。
5. 编译并下载至 MSPM0G3507 开发板。
6. 上电后通过 OLED 菜单选择任务，使用启动按键运行，必要时通过停止按键急停。

本项目依赖具体的 TI 开发环境及硬件配置。若仓库未包含完整工程文件或相关 SDK 依赖，需要根据实际文件补齐后再编译。

## 🔧 调试与标定

- **电机方向错误**：检查左右轮接线及 `MOTOR_L_REVERSE`、`MOTOR_R_REVERSE` 配置。
- **纠偏方向错误**：检查 `CTRL_DIR_SIGN`，必要时修改为 `-1`。
- **灰度极性相反**：检查 `GRAY_LINE_ON_HIGH` 配置。
- **灰度探头顺序错误**：调整 `gray.c` 中传感器读取顺序。
- **EVENT2 停车位置不准**：调整 `EVENT2_BRAKE_OFFSET_MS` 并反复实测。
- **EVENT4 距离不准**：重新标定 `ODO_PULSE_PER_METER`，确认左右轮脉冲累计口径。
- **编码器计数异常**：检查中断 pending 标志处理及编码器接线。

## ⚠️ 已知限制

- 当前编码器主要使用 A 相计数，不判断旋转方向，也不参与电机速度闭环。
- 蜂鸣器和 LED 驱动已编写，但当前主流程未实际调用。
- EVENT3 使用本地计时结束任务，没有接收摆杆控制板的完成状态反馈。
- EVENT2 的武装时间为固定值，改变赛道长度或速度后需要重新调整。
- 里程系数需要根据实际轮径、编码器参数和脉冲统计方式校准。
